# MIC Product Assistant

这是一个本地 Chrome 插件，用来提取 Made-in-China 产品编辑页表单上下文，并把 Hermes agent / AI 生成的产品资料文本自动填入 Made-in-China 产品上传/修改页面。

插件现在按页面板块填充，不再用全页面字段猜测。每个板块会先绑定自己的 DOM 区域，再只在这个区域里查找和填写输入框，避免 A 板块的信息误填到 B 板块。

## 安装

1. 打开 Chrome，进入 `chrome://extensions/`
2. 打开右上角“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择这个文件夹：

   ``<插件解压目录>/mic-product-assistant``

## 使用

1. 打开 Made-in-China 产品上传或修改页面
2. 点击浏览器右上角插件图标
3. 粘贴 Hermes skill 生成的产品资料
4. 点击“填充当前页面”

也可以先复制好整段资料，然后点“读取剪贴板并填充”。

## 一键提取产品信息

在 MIC 产品上传或编辑页面点击“一键提取并复制”，插件会读取当前页面可回填的表单字段，把结构化 JSON 放入插件文本框并复制到剪贴板。该 JSON 可直接交给 AI，内容包括：

- 字段所在板块、字段名、当前值、必填状态、控件类型和平台可选值
- `bulkFillFieldName` 兼容字段名，表示 AI 生成回填文本时应该使用的字段名
- `domLocator` 轻量 DOM 定位信息，便于和页面字段绑定规则对照
- MIC 默认标准属性与固定属性
- 用户通过“添加自定义属性”手动新增的属性
- 当前定价模式及该模式下正在启用的价格字段

`select`、`radio`、`checkbox` 字段会包含 `options: [...]`，让 AI 知道优化值必须从 MIC 平台选项中选择。`产品展示` 和 `产品详情` 不参与一键提取。`运费信息` 中的 `运费模板` 会从当前页面提取为真实 select 字段及 options；默认选择“官方物流运费模板（默认推荐）”，选项不存在时不虚报成功。

从插件 0.2.23 起，提取结果还会包含 contractVersion: 1.1 和 capabilities。capabilities 描述当前插件/页面可执行能力，例如单选中心词、当前已渲染关键词槽位、是否支持继续添加关键词、插件关键词协议技术输入上限、亮点/FAQ 技术能力。这些 ceiling 字段只描述插件能处理多少输入，不代表 MIC 平台当前允许/推荐填写多少。AI/Hermes 应由当前 EAO MIC Platform Rules 决定业务数量，并用运行时能力确认页面/插件是否能执行。

提取结果里的 `fieldName` 表示当前页面的具体表单槽位，`bulkFillFieldName` 表示生成回填文本时应使用的字段名。例如多个规格值槽位会提取为 `规格1值1`、`规格1值2`，但它们的 `bulkFillFieldName` 都是 `规格值`，AI 应生成 `规格值：A; B`。

如果 `规格管理` 模块存在但当前没有渲染任何规格输入框，提取结果会保留该 section，并标记 `exists: true, empty: true`；同时输出 `规格1名称` 和 `规格1值1` 两个空值骨架字段，分别映射到 `bulkFillFieldName: 规格名称` / `规格值`，提醒 AI 这个必填评分模块需要补充。

产品属性的来源由 DOM 结构判定：`.J-stand-prop` 是 MIC 标准属性，固定的运输包装/规格/商标/原产地是 MIC 固定属性，`.J-selfprop` 中的属性名和值是手动添加的自定义属性，不依赖字段名称猜测。

## 导出类别表单 Schema

当你想为某个 MIC 类别建立可复用模板时，打开该类别任意一个真实产品编辑页，点击“导出类别表单”。

插件会输出：

`schema: "mic-category-form-schema/v1"`

这个 Schema 用来告诉 AI：

- 当前类别实际有哪些可回填字段
- 每个字段属于哪个板块
- `bulkFillFieldName`
- 是否必填
- 控件类型
- MIC 当前可选项
- 当前插件/页面 capabilities

类别 Schema 会主动删除当前产品已经填写的值，也会排除这个产品手工新增的自定义属性，避免把某一个产品的 24V、IP 等级、价格或自定义属性污染成整个类别的固定规则。

因此两个导出入口用途不同：

- “提取当前产品” → `mic-product-edit-context/v1`，保留当前值，用于优化已有 Listing。
- “导出类别表单” → `mic-category-form-schema/v1`，只保留结构，用于同类别产品复用。

如果 MIC 后续修改了该类别表单，重新打开真实编辑页导出一次即可更新 Schema。

## 文本格式

每个板块使用 `# 板块名称`，每个字段使用 `字段名：内容`。

板块顺序必须按页面视觉顺序输出：

1. `# 基本信息`
2. `# 产品亮点`
3. `# 产品属性`
4. `# 规格管理`
5. `# FOB价格设置`
6. `# 计量单位`
7. `# 包裹尺寸`
8. `# 运费信息`
9. `# 发货效率信息`
10. `# 样品单交易设置`
11. `# 其他信息设置`
12. `# FAQ`

## 关键规则

- 产品属性不存在跨类别通用的固定字段集合；以当前编辑页 Context 或已保存的 Category Form Schema 为准。
- 标准属性的 `options` 必须按 MIC 当前页面提供的选项处理，不要从旧类别模板猜测。
- 当前编辑页 Context 的优先级高于已保存的 Category Form Schema，因为 MIC 可能调整类别字段。
- `中心词` 页面为单选；插件会从当前候选中匹配并同步单一选择。
- 插件的 `keywordPluginInputCeiling` 只是技术输入上限，不代表 MIC 当前业务规则允许或推荐填写多少关键词。
- `FOB价格设置` 会根据实际输出字段选择一口价/阶梯价/区间价；不要混用多种价格模式字段。
- `规格管理` 与 FOB 定价模式相互独立。
- `运费信息` 的 `运费模板` 属于 canonical Bulk Fill 文本；只有当前页面实际支持的选项才可回填。`产品展示` 与 `产品详情` 仍不属于 canonical Bulk Fill。
- 未知价格、MOQ、包装、港口、认证、IP、交期等值必须留空，由上游 EAO 事实层决定，插件不负责猜测。

## 推荐入口

在 EAO 中优先使用 `armor-mic-product-optimization` 做产品事实、关键词、类别 Schema 和 Listing 决策；本仓库中的 `mic-made-in-china-fill` 只维护 Chrome Bulk Fill 文本协议，不再承担产品知识或 MIC 运营策略。

## 0.3.1｜FAQ 与标准属性回填保护

- FAQ 技术回填上限由 10 组增加到 12 组；实际可回填数量仍取决于编辑页存在的 FAQ 行与添加按钮。
- 当前编辑上下文中的 MIC 标准属性新增 `otherInputSupported`，表示此字段在提取时是否存在实际的“其他”自定义输入框。
- 当目标值不在标准属性下拉选项内，且页面不存在自定义输入控件时，插件不再仅选择 `Other` 并把字段虚报为已完成。
- 更新后在 Chrome 扩展程序页面点击“重新加载”，重新提取 MIC 产品 JSON，以获取正确的 `faqPluginInputCeiling: 12` 和自定义输入能力信息。
- **注意**：插件只负责表单字段映射，不会验证产品型号、认证或价格。提交 MIC 页面前仍需检查实际保存结果。

## 0.3.2｜V2 运费模板支持

- 产品编辑上下文和类别表单 Schema 增加“运费信息 / 运费模板”字段、选项和实际已选值。
- `capabilities.shippingTemplateBulkFill` 标明页面是否存在可填的运费模板 select 控件。
- `capabilities.customAttributeAddSupported`、`customAttributeSlotsRendered`、`customAttributePluginInputCeiling` 为 V2 分批优化提供实际页面容量；新增属性会在 DOM 中与标准/固定属性做名称及常见中英同义项去重，不保证自动检测所有语义重复。
- 插件支持 `# 运费信息` 下的 `运费模板：官方物流运费模板（默认推荐）`，省略时仍采用官方默认选项。
- 如果默认选项不存在或写入失败，不再将其误报为已填充。
- 安装更新后必须在 Chrome 扩展程序页面重新加载，再重新提取页面 JSON；以前的 11 板块导出不包含运费模板。

## 0.3.3｜显式 Other 合法选项回填

- 用户明确要求选择 **Other** 且当前 MIC select 实际包含该选项时，按合法选项直接选择，不再误判为空值/占位符。
- 当下拉没有 Other 时不可硬填；需要表示具体自定义技术数值时，仍要求真实的 Other 附加输入框，否则不报告成功。
- 导出能力新增 `explicitOtherOptionSupported: true`；旧版导出没有该标志，EAO V2 校验只能报告部分可回填。
- 用 `node tests/test-explicit-other.cjs` 运行插件端的最小回归测试。
